# Полная пошаговая инструкция по запуску из GitHub

Инструкция предназначена для запуска `MrSystemC/parimbank` с чистого устройства. Она описывает локальную разработку, первый вход владельца, проверку приложения, обновления и публикацию на Cloudflare.

## 1. Что получится после запуска

После выполнения инструкции будут доступны:

- сайт с локальной базой D1;
- собственный вход по логину и паролю;
- первичная настройка владельца через `/setup`;
- регистрация участников через `/register`;
- личный кабинет пользователя;
- административная панель по адресу `/admin`;
- создание розыгрышей, категорий, запросов монет и сообщений;
- загрузка изображений призов при подключённом R2.

Новая локальная база создаётся пустой. Готовые розыгрыши, участники и билеты автоматически не добавляются.

## 2. Требования

| Компонент | Требование |
| --- | --- |
| Node.js | 22.13 LTS или новее в пределах поддерживаемой LTS-линейки |
| npm | Устанавливается вместе с Node.js |
| Python | Python 3 для полного набора тестов |
| Git | Для клонирования и обновления репозитория |
| Операционная система | Linux, Windows через WSL, macOS или Debian внутри Android |
| Production | Cloudflare Worker, D1, R2 и домен с HTTPS |

### Важное ограничение Android

Нативный Termux работает как Android-окружение, а не как обычный Linux. Cloudflare `workerd`, который нужен этому проекту, не запускается напрямую на `android arm64`.

На Android используйте Debian через `proot-distro` или полноценный rootful Linux-контейнер. Не переносите в Debian папку `node_modules`, установленную в нативном Termux.

## 3. Клонирование репозитория

Откройте терминал и выполните:

```sh
git clone https://github.com/MrSystemC/parimbank.git
cd parimbank
```

Проверьте, что используется основная ветка:

```sh
git branch --show-current
git pull --ff-only origin main
```

Если Git попросит авторизацию для чтения публичного репозитория, проверьте адрес и сетевое подключение. Для обычного клонирования публичного репозитория токен не требуется.

## 4. Подготовка Android через Debian

Эти команды выполняются в нативном Termux:

```sh
pkg update
pkg upgrade -y
pkg install proot-distro -y
proot-distro install debian
proot-distro login debian
```

Внутри Debian установите инструменты:

```sh
apt update
apt upgrade -y
apt install -y curl git python3 build-essential ca-certificates
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs
node --version
npm --version
```

Если проект находится в общей папке Termux, перейдите к нему из Debian:

```sh
cd /data/data/com.termux/files/home/parimbank
```

Если этот путь недоступен, клонируйте репозиторий заново внутри Debian:

```sh
cd /root
git clone https://github.com/MrSystemC/parimbank.git
cd parimbank
```

## 5. Установка зависимостей

В корне репозитория выполните:

```sh
rm -rf node_modules dist .vinext
npm ci
```

`npm ci` использует зафиксированный `package-lock.json` и устанавливает зависимости с нуля. Не копируйте `node_modules` с другой операционной системы или архитектуры.

Проверьте состояние проекта:

```sh
npm run typecheck
npm run lint
```

## 6. Создание локальной конфигурации

Создайте файл `.dev.vars` из безопасного примера:

```sh
cp config/env.example .dev.vars
```

Если файл уже существует, сохраните его резервную копию и не перезаписывайте без необходимости:

```sh
cp .dev.vars .dev.vars.backup
```

`.dev.vars` не нужно загружать в GitHub. Логин и пароль владельца через этот файл не задаются. Они создаются в приложении на странице `/setup`.

## 7. Сборка проекта

Сначала создайте production-конфигурацию Worker:

```sh
npm run build
```

Успешная сборка должна завершиться сообщением `Build complete`. После неё должен существовать файл:

```sh
test -f dist/server/wrangler.json && echo "wrangler config OK"
```

Если сборка не завершилась, не запускайте миграции. Ошибка `dist/server/wrangler.json: ENOENT` означает, что сборка была остановлена раньше.

## 8. Создание локальной базы и миграции

После успешной сборки примените миграции:

```sh
npm run db:migrate:local
```

Повторный запуск безопасен:

```sh
npm run db:migrate:local
```

Сообщение `No migrations to apply!` означает, что текущая локальная база уже содержит все миграции.

Локальное состояние сохраняется в `.wrangler/state`. Не удаляйте этот каталог, если в нём находятся нужные данные.

## 9. Запуск dev-сервера

Запустите приложение:

```sh
npm run dev
```

Откройте адрес, который напечатан в терминале. Обычно это:

```text
http://localhost:5173
```

Для другого порта:

```sh
npm run dev -- --port 5174
```

Остановить сервер можно сочетанием `Ctrl+C`.

## 10. Первый запуск и создание владельца

Откройте в браузере:

```text
http://localhost:5173/setup
```

Заполните логин владельца, пароль и отображаемое имя.

Первый созданный аккаунт получает роль владельца. После завершения настройки используйте:

```text
/setup       первичная настройка, только один раз
/login       вход
/register    регистрация участника
/admin       административная панель
/telegram    подключение Telegram-кабинета
```

Страница `/setup` закрывается после создания первой учётной записи. Пароли не записываются в открытом виде. Сессия хранится в защищённой HttpOnly-cookie.

## 11. Проверка пользовательского кабинета

Создайте отдельный обычный аккаунт через `/register` и проверьте:

1. вход через `/login`;
2. отображение нулевого баланса;
3. разделы билетов, результатов и сообщений;
4. отправку запроса на пополнение монет;
5. запрет доступа к `/admin`;
6. выход через профиль.

Обычный пользователь не получает административные права только из-за регистрации. Роль назначается владельцем или уполномоченным администратором.

## 12. Проверка административной панели

Войдите аккаунтом владельца и откройте `/admin`.

Проверьте разделы:

- обзор;
- розыгрыши;
- категории;
- запросы монет;
- пользователи;
- сообщения;
- операции;
- настройки;
- журнал аудита;
- руководство.

Создайте тестовую категорию, затем тестовый розыгрыш с призом, количеством билетов и ценой. Перед production замените тестовые данные реальными условиями и призами.

## 13. Полная автоматическая проверка

Выполните:

```sh
npm run check
npm run build
```

Для отдельной проверки миграций на новой базе:

```sh
npm run db:migrate:local -- --persist-to .wrangler/migration-check
npm run db:migrate:local -- --persist-to .wrangler/migration-check
```

Проверки используют изолированные базы и не должны менять рабочую локальную базу.

## 14. Запуск собранного Worker

После `npm run build` можно проверить собранный Worker:

```sh
npm start
```

Этот режим локальный. Он не публикует сайт в интернете и использует локальные D1/R2-привязки.

Если Wrangler сообщает об ошибке сетевого интерфейса в ограниченном окружении, проверьте dev-сервер и сборку в Debian, WSL, обычном Linux или Cloudflare. Такая ошибка может быть ограничением среды запуска, а не ошибкой исходников.

## 15. Production через Cloudflare

Для production нужны Cloudflare Worker, D1 Database, R2 Bucket, домен с HTTPS, применённые миграции, резервное копирование, уникальные данные владельца и серверные секреты Telegram при необходимости.

Порядок:

1. Создайте Worker в Cloudflare.
2. Подключите D1 к binding `DB`.
3. Подключите R2 к binding `BUCKET`.
4. Убедитесь, что в конфигурации проекта указаны правильные binding-имена.
5. Выполните production-сборку.
6. Примените все SQL-миграции к production D1.
7. Опубликуйте Worker.
8. Откройте опубликованный адрес `/setup`.
9. Создайте владельца.
10. Проверьте `/login`, `/register`, `/admin` и `/api/auth/session`.
11. Проверьте загрузку изображения приза в R2.

Не переносите локальную `.wrangler/state` в production. Production D1 и R2 должны иметь отдельные резервные копии.

Подробная инструкция по бесплатному Telegram Worker находится в [CLOUDFLARE_RU.md](../bot/CLOUDFLARE_RU.md).

## 16. Обновление уже установленной копии

Перед обновлением сохраните резервные копии D1 и R2. Затем выполните:

```sh
git pull --ff-only origin main
npm ci
npm run typecheck
npm run lint
npm test
npm run build
npm run db:migrate:local
```

Не редактируйте уже применённые SQL-файлы. Новые изменения схемы добавляйте отдельной миграцией.

## 17. Частые ошибки

| Ошибка | Решение |
| --- | --- |
| `Unsupported platform: android arm64 LE` | Запустите проект внутри Debian через `proot-distro`, а не напрямую в Termux |
| `dist/server/wrangler.json ENOENT` | Сначала исправьте ошибку `npm run build`, затем повторите миграцию |
| `No such table` | Запустите `npm run db:migrate:local` в том же каталоге проекта |
| `EEXIST .dev.vars` | Файл уже создан, используйте его или сделайте резервную копию |
| `npm ci` использует неправильные native-пакеты | Удалите `node_modules` и выполните установку внутри текущей Linux-среды |
| `/admin` возвращает на `/login` | Войдите владельцем или назначьте аккаунту роль в разделе «Пользователи» |
| Не загружается изображение | Проверьте binding `BUCKET`, формат JPEG/PNG/WebP и лимит 5 МиБ |
| Порт уже занят | Остановите старый процесс или используйте `npm run dev -- --port 5174` |
| Android останавливает сервер | Отключите оптимизацию батареи, включите `termux-wake-lock` и используйте Termux:Boot |
| Не работает Telegram | Проверьте токен, username, `TELEGRAM_BRIDGE_SECRET` и отдельную настройку транспорта |

## 18. Безопасность

- Не публикуйте `.dev.vars`, `.env*`, токены, пароли и резервные копии.
- Не используйте пароль владельца в тестовых примерах.
- Не открывайте D1 и R2 напрямую в интернет.
- Используйте HTTPS для production.
- Ограничьте доступ к SSH и административной панели.
- Включите резервное копирование до применения миграций.
- Не используйте мобильный телефон как единственный носитель production-данных.

## 19. Минимальный быстрый сценарий

Для обычного Linux, WSL или Debian выполните:

```sh
git clone https://github.com/MrSystemC/parimbank.git
cd parimbank
npm ci
cp config/env.example .dev.vars
npm run build
npm run db:migrate:local
npm run dev
```

Затем откройте `http://localhost:5173/setup` и создайте владельца.
